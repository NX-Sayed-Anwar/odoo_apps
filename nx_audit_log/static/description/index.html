THE PROBLEM

Odoo shows what your data is. It does not prove who changed it.

Changes leave no trace

Most fields are not tracked. An invoice total, a price or a supplier IBAN can change and the old value is lost.

Deletions erase everything

A deleted record is gone. Nobody can say what it contained, or who removed it.

Nothing is provable

Chatter can be deleted, server logs are technical, exports and API reads leave no trace.

THE SOLUTION

Evidence, not messages: every change recorded, sealed and searchable

Captures automatically

Under the ORM and at the request boundary, in the same transaction as the business change. Rolled back = no evidence; committed = always evidence.

Proves nothing was altered

Evidence is read-only for everybody and sealed into HMAC-SHA256 hash chains verified every day.

Warns you in time

Alerts on deleted entries, changed totals or bank accounts, privilege changes, mass deletion and brute force.

Key features

FIELD-LEVEL EVIDENCE

Every field, old → new, with its origin

  • User, date, IP, user agent, session and source decided by the server (Web UI, JSON-RPC, XML-RPC, cron, import, automated / server action).
  • Before and after values read from the database: what was really stored.
  • Each line labelled Direct, Derived (recomputed) or Database cascade.
  • One2many lines and many2many links (both sides) included.
DELETED-RECORD FORENSICS

Deleted, but not forgotten

  • Full delete snapshot of every stored field.
  • Child events for lines deleted with the record and links cleared by PostgreSQL.
  • Refused deletions recorded as failed operations.
RECORD TIMELINE

The whole story of a record on one screen

  • Action ⚙ → Audit Trail on every audited model.
  • Changes of owned lines in the same timeline.
  • Old values struck through, derived changes on demand.
DATA ACCESS & SECURITY

Know who took the data

  • Exports, printed reports, imports (as batches with counters).
  • API reads above a threshold (500 records by default) with client and IP.
  • Login, logout, second factor, failed logins grouped by login + IP + window.
  • Users, groups, access rights, record rules, API keys and system parameters audited by default; secrets never stored.
ALERTS

The right person is told within minutes

  • Ready-made: journal entry deleted or deletion blocked, invoice total changed > 10 %, bank account number changed, user groups changed, mass deletion, brute force.
  • Triggers: delete, failed operation, field change (any / absolute / percent), mass delete, failed logins, business action.
  • Created with the evidence (never for a rolled-back change), deduplicated, capped per hour; chatter notification + To Do activity.
INTEGRITY

Tamper-evident by design

  • No create / write / delete rights on evidence, for anybody.
  • HMAC-SHA256 hash chain per company and year, key kept in odoo.conf.
  • Daily verification: missing event, broken link, modified event or value, invalid checkpoint, truncated tail.
RETENTION & PRIVACY

Keep what the law requires, erase what it allows

  • Policies: online → archived (searchable) → tombstone → signed checkpoint. Finance evidence can never be purged.
  • Sensitive patterns: secrets never stored, personal data flagged or stored as keyed digest.
  • Four-eyes redaction for data-subject requests: plain values removed, proof still valid.
CONTROL

You decide what is recorded

  • Rule per model or for all business models, by company, domain, user, group or source.
  • All / selected / all-except fields, secret fields, direct or derived changes.
  • Default rules for finance, sales, purchase, inventory, contacts and security, created for the installed apps.
  • Fail mode: keep business running, or block the transaction if evidence cannot be written.
